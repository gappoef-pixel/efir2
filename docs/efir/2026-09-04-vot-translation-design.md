# «Эфир 2»: закадровый перевод роликов через Yandex VOT

Дата: 2026-09-04. Статус: дизайн утверждён, реализация не начата.

## 1. Задача

Дать в плеере кнопку «Перевод»: англоязычный (и любой иностранный) ролик озвучивается
по-русски поверх оригинала — так же, как это делает Яндекс.Браузер. Сервис Яндекса
неофициальный, но открытый: протокол разобран в `vot.js` / `yavot-py`.

## 2. Что установлено спайком 04.09.2026 (факты, не предположения)

Проверено с рабочего Мака, российский IP, без аккаунта и без оплаты:

| Замер | Результат |
|---|---|
| Ролик 3:33, отсутствовал в кэше Яндекса | готово за 83 с |
| Он же повторно | 0,4 с |
| Ролик 11:30, Яндекс его раньше не видел | ~4–5 мин, далее 0,4 с |
| Скачивание готовой дорожки (3,4 МБ) | 0,8 с |

Формат выдачи: подписанная ссылка `https://vtrans.s3-private.mds.yandex.net/tts/prod/<id>.mp3`,
`X-Amz-Expires=7200` (2 часа). Аудио: MP3, mono, 22050 Гц, 128 кбит/с, ≈1 МБ на минуту видео.

Дорожка **выровнена по таймлайну видео целиком** (для ролика 213 с длина 213,16 с) и содержит
**только голос переводчика**: `silencedetect -40dB` находит 26 пауз, первые 18,5 с — тишина под интро.
Оригинального звука в ней нет. Следствие: сводить оригинал и перевод должны мы сами.

Ответ сервиса честно ведёт обратный отсчёт в `remainingTime` (51 → 29 → 9 → 5), поэтому оценку
времени ожидания показываем пользователю из этого поля, а не выдумываем.

## 3. Принятые решения

1. **Ожидание не блокирует просмотр.** Видео играет с оригинальным звуком, готовая озвучка
   подхватывается на лету с текущей позиции. Экрана ожидания нет.
2. **Включение — только вручную, кнопкой.** Автоопределения языка нет: поля `defaultAudioLanguage`
   в парсере `MediaServiceCore` нет, а каждый ошибочный запрос заставляет Яндекс молоть минуты.
3. **Сведение — вторым экземпляром плеера**, а не средствами одного ExoPlayer.
4. **Protobuf кодируется вручную**, без gradle-плагина кодогенерации.

Обоснование 3: `MergingMediaSource` со вторым аудиорендерером дал бы идеальную синхронизацию,
но включение перевода потребовало бы пересборки медиа-источника, то есть перезапуска видео с
ребуферизацией — что несовместимо с решением 1, — и правки в конвейере DASH/SABR, самой хрупкой
части SmartTube. Точность 100–300 мс для закадрового голоса на слух незаметна; в Яндекс.Браузере
схема ровно такая же (отдельный `<audio>` + приглушение оригинала).

Обоснование 4: сообщение фиксируется один раз и не меняется, а плагин кодогенерации в сборке,
где ради успешного билда уже отключается `lintVital`, — лишний источник поломок.

## 4. Архитектура

Три новых куска и три строки правок в существующем коде.

### 4.1 `common/.../common/vot/` — сетевой слой (не знает о плеере)

- `VotCrypto` — HMAC-SHA256 подпись тела и токена, заголовки Яндекс.Браузера.
  Ключ `bt8xH3VOlb4mqf0nqAibnDOoiPlXsisf`, `COMPONENT_VERSION = 26.4.1.1026` (публично известны).
- `VotProto` — ручная сборка `VideoTranslationRequest` и разбор `VideoTranslationResponse`.
- `VotClient` — `createSession()`, `translate(videoId, srcLang, dstLang)` → `{ready, audioUrl, remainingSec, status}`,
  внутренний `sendFailAudio(videoId)`. Транспорт — OkHttp (в проекте есть).

**⛔⛔ Заголовки запроса — проверено на живом сервисе 04.09.** Тип содержимого — **`application/x-protobuf`**,
а НЕ `application/protobuf`: на второй вариант Яндекс отвечает `415 Unsupported Media Type`.
Полный набор, как у эталонной реализации: `Content-Type: application/x-protobuf`, `Accept: application/x-protobuf`,
`Accept-Language: en`, `Pragma: no-cache`, `Cache-Control: no-cache` плюс `User-Agent` Яндекс.Браузера и три заголовка подписи.
🔑 Урок: эталонные векторы покрывали тело запроса и подписи, но не заголовки — и ошибка доехала до устройства.

Хост `api.browser.yandex.ru`, пути `/video-translation/translate`, `/video-translation/fail-audio-js`.
`sendFailAudio` обязателен для роликов, которых Яндекс раньше не видел, — без него ролик не берётся в работу.

**⛔ Форма ссылки важна.** Яндексу отправляется нормализованный `https://youtu.be/<videoId>`,
а не `https://www.youtube.com/watch?v=<videoId>`: ветка дозаявки ролика (status 6 → `fail-audio-js`)
в рабочей реализации срабатывает только на форму `youtu.be/`.

`duration` берётся из текущего `Video` в плеере; если длительность неизвестна — 310 (значение по умолчанию
в рабочей реализации). `language` шлём `en` с `forceSourceLang=false` — Яндекс уточняет язык сам и при
расхождении возвращает его в поле `language` ответа; в этом случае делаем один повторный запрос с
подсказанным языком.

Поля запроса (номера — из `yandex.proto`): `url=3`, `firstRequest=5`, `duration=6`, `unknown0=7 (1)`,
`language=8`, `forceSourceLang=9`, `unknown1=10 (0)`, `wasStream=13`, `responseLanguage=14`,
`unknown2=15 (1)`, `unknown3=16 (2)`, `bypassCache=17`, `useLivelyVoice=18`, `videoTitle=19`.

Статусы ответа: `0` FAILED, `1` FINISHED, `2` WAITING, `3` LONG_WAITING, `5` PART_CONTENT,
`6` AUDIO_REQUESTED, `7` SESSION_REQUIRED.

**⛔ `bypassCache` не выставлять никогда.** В протоколе прямо указано: после одного такого запроса
сервис перестаёт отвечать этому IP.

### 4.2 `TranslationController extends BasePlayerController`

Конечный автомат на ролик: `OFF → REQUESTED → PREPARING → PLAYING`.

- Опрос через RxJava с интервалом из `remainingSec` (нижняя граница 5 с), потолок ожидания 10 минут.
- По готовности: поднять второй `SimpleExoPlayer` (только аудиорендереры), скормить S3-ссылку,
  перемотать на позицию основного, основному `setVolume(0.15)`, играть.
- Зеркалирование событий: `onPlay`, `onPause`, `onSeekEnd`, `onSpeedChanged`, `onEngineReleased`, `onFinish`.
- Контроль дрейфа: тик 1 с, при расхождении > 300 мс — перемотка второго плеера.
- Выключение: вернуть громкость, освободить второй плеер. Видео не перезапускается.

### 4.3 UI

- Флаг `PLAYER_BUTTON_TRANSLATION = 1 << 28` в `PlayerTweaksData`, включён в `PLAYER_BUTTON_DEFAULT`.
- ⛔⛔ **Умолчания недостаточно для уже установленного приложения.** Маска кнопок хранится файлом
  `files/app_prefs/video_player_tweaks_data` (НЕ в `shared_prefs`), и при обновлении читается сохранённое значение,
  а не новый дефолт: кнопка молча не появляется. Нужна разовая миграция маски (добавить бит существующим установкам,
  с возможностью потом выключить руками). Проверено 04.09 на X5M `.64`: в файле лежало `140032` = старый дефолт.
- Действие на два состояния (выключено / включено) — прямой наследник `TwoStateAction`.
  Отдельного состояния «готовится» у кнопки нет: нажатие сразу переводит её в «включено», а ход
  подготовки показывают тосты («Готовим озвучку, ~N», затем «Перевод включён»). Третье состояние
  потребовало бы своего базового класса с тремя иконками — цена не окупается, поскольку ожидание
  и так озвучено текстом с оценкой времени.
- Регистрация в `VideoPlayerGlue`, пункт в `PlayerSettingsPresenter` (список кнопок).
- Раздел настроек «Перевод видео»: громкость оригинала (10/15/25/50 %, по умолчанию 15),
  язык перевода (по умолчанию `ru`).

### 4.4 Правки в существующем коде (весь диф в чужих файлах)

1. `PlaybackPresenter` — одна строка регистрации контроллера.
2. `PlayerTweaksData` — константа флага и её добавление в дефолт.
3. `VideoPlayerGlue` + `PlayerSettingsPresenter` — кнопка и пункт настроек.

Апстрим-обновления такое переживают: слияние идёт по значениям и спискам, а не по вёрстке.

## 5. Ошибки и краевые случаи

| Случай | Поведение |
|---|---|
| Ссылка протухла на длинном ролике (403 у второго плеера) | перезапросить перевод (кэш, 0,4 с) и продолжить с текущей позиции |
| Status 0 (нет речи, слишком длинный) | тост с причиной, кнопка гаснет, повторов нет |
| Ожидание > 10 мин | сдаёмся с сообщением |
| Нет сети / 5xx | тост, состояние OFF, без шторма повторов |
| Смена ролика во время подготовки | опрос снимается, «хвост» не всплывает |
| Прямой эфир | кнопка недоступна (у Яндекса отдельный API с пингами) |

**Живьём — только на X5M `X5M (тестовая приставка в локальной сети)`** (правило обкатки «Эфира»): подхват на лету, пауза,
перемотка, дрейф на ролике 20+ минут, смена видео в момент подготовки, выключение перевода.

## 7. Чего в этом заходе нет (осознанно)

Автоопределение языка ролика; предварительная постановка переводов в очередь; субтитры Яндекса;
прямые эфиры; режим «живого голоса» (`useLivelyVoice` — качество плавает от диктора к диктору).

## 8. Риски

- API неофициальный: Яндекс может сменить версию компонента или ключ подписи. Лечится обновлением
  двух констант вслед за `vot.js`.
- Ожидание 1–5 минут на непереведённом ролике — свойство сервиса, а не наша задержка; смягчено тем,
  что просмотр не блокируется.
- Дрейф синхронизации на длинных роликах — снимается тикером досинхронизации, порог 300 мс подлежит
  проверке на живом железе.
